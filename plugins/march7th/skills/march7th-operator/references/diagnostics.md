# 诊断依据

先明确是在解释配置、检查保存、分析执行失败还是要求修复。只检查时不试跑会消费资源、改写记录或触发收尾动作的任务，不把效果优化扩大成用户未要求的变更。

按实际证据区分：自己的对象或参数不符合契约、任务未开放、宿主状态变化、连接或主线程派发失败、游戏前提未满足，以及业务执行失败。状态查询正常时不能把业务拒绝说成桥断开；连接不可用也不能推出游戏进程不存在。

配置效果要从本次实际启用项、参数定义与使用分支判断。可读但不可写、未启用选项、默认继承、旧字段残留和正在执行的任务已读取旧配置分别说明，不从单个配置值推断整个行为。

源码只能解释相应版本；需要确认本机正在执行哪个实现，再跟踪相关分支、等待、异常与结束条件。界面说明、代码注释或一条泛化错误不能单独证明根因，尤其不能用猜测队伍、连接或图像条件代替证据。

能安全修正自己的调用时按当前契约修正。明确的宿主拒绝说明具体阻碍；未知结果先核实。没有已证实的恢复入口就不编造按钮、开关或让用户重启；桥覆盖缺口与软件自身不支持应分开报告。
