# 准备、执行与停止

从本次任务能力确认接收的对象、准备条件、影响范围及返回含义。配置和目录查询通常不需要游戏已就绪；不要为查设置启动游戏。真正执行时，宿主是否负责启动、登录后等待或其他准备，以当前说明为准，不例行要求用户重复准备。

沿用已有有效配置，只检查实际任务需要的前提。保存了队伍或选填项目不代表必须重问；未使用的旧字段也不是本次缺项。遇到已有任务占用时先核对其身份与状态，不擅自停止、改写任务或另开并行进程。

三月七的启动接纳以观察到执行进程或宿主任务进入运行状态为依据，和仅调用了一次启动方法不同。已调用但没有确认时只报告未确认，再按当前能力核实；不能重新提交启动来试探。

用户只要求开始运行时，确认启动后结束本轮，不继续读取日志、截图或状态作为附加监控。当前桥提供状态和界面日志读取，没有专用的业务完成等待或订阅入口。用户要求等结果时，先核对外层任务系统能否用受控等待和真实结果闭合链路；缺少这一环就明确说明，不能编造等待接口，也不能用模型反复轮询或固定等待充当完成。

停止要核实实际任务及其结果。进程未在运行、仍在启动、请求停止和已确认停止分别表述；宿主存在待处理的收尾动作时，也不能仅凭进程空闲就断言所有后续动作已取消。回执未知就只说未知，不关闭宿主或杀进程冒充已停止。
