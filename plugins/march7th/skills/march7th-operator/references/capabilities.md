# 能力发现与边界

先区分三类事实：软件源码声明了什么，当前桥登记了什么，当前宿主实例此刻能调用什么。静态资料和历史版本只能解释对应实现，不能替代本次工具契约；查到内部类或公开方法，也不能把它当成可直接反射的调用入口。

当前适配主要围绕内置任务、宿主配置及界面日志。任务目录还受到桥允许范围与当前宿主实际任务清单的共同限制；不是把整个软件的所有按钮、扩展和维护操作都开放给模型。

名称未命中时先核对业务含义、查询范围、目录版本与是否读取完整。目录查询失败不能当作空结果，空结果也不能证明软件本体没有此能力。已经找到候选时先读其用途和限制，不继续穷举同义词或把相似任务拿来试跑。

若源码存在实现而桥没有入口，应明确这是适配覆盖缺口；若入口存在但对象或界面线程不可用，应排查运行上下文。不能靠新造接口名、调用任意反射方法、打开未知页面、终端或模拟点击来补齐缺口。

需要阅读源码或说明时，使用当前可用且已授权的资料能力；插件没有提供源码索引时不能假称已检索。只读分析不授予修改宿主、下载更新、安装依赖或运行任务的权限。

遇到本轮常规目录或接口已经证实的覆盖缺口、契约变化或不可用时，才按需读取[缺口补足](gaps.md)。这不是正常操作的前置步骤。
