# 日志与业务结果

三月七的日志能力读取现有界面中的文本，不是为每次请求生成一份独立的业务报告。日志可能包含旧任务、手工操作和前次失败；不能看到末尾“完成”就判定当前任务成功。

只为用户要求的进展、结果或诊断读取必要范围。结合任务身份、观察时刻以及可用的前后文建立本次对应关系；尾部被截断时继续相关范围，没有身份或时间证据时承认无法归属。不能编造唯一运行记录或把宿主任务标识当成每次运行的独立记录编号。

启动确认只证明任务已经开始。进程退出或宿主恢复空闲还不足以证明挑战成功、目标资源消耗完毕或奖励到账；需要属于本次任务的明确结果或日志依据。未知输出、日志暂空和实际失败分别处理。

停止核实只覆盖停止阶段，不能自动解释此前已经发生的游戏行为。被取消、自然结束、执行异常和目标已完成不能仅靠同一个空闲状态区分。

面向用户只说实际任务名、当前阶段和可确认的结果。没有日志支持的进度、耗时、收益、角色缺失或根因，不作为结论；普通启动请求不为凑“完整结果”而追加后台监控。
